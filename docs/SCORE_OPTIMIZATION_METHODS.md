# F5-TTS 分数优化方法总结

## 📊 优化目标

提高 TTS 生成音频的客观评估指标分数，包括：
- **PESQ** (感知语音质量): 1.0-4.5，越高越好
- **STOI** (短时客观可懂度): 0.0-1.0，越高越好
- **CSIG/CBAK/COVL** (综合质量指标): 1.0-5.0，越高越好
- **DNSMOS** (DNS挑战MOS分数): 越高越好
- **SRMR** (语音质量指标): 越高越好

## ✅ 已实施的优化方法

### 1. 推理参数优化 ⭐⭐⭐⭐⭐

**关键参数调整：**

| 参数 | 优化前 | 优化后 | 影响 |
|------|--------|--------|------|
| `nfe_step` | 100 | **150** | 提高采样步数，显著提升生成质量 |
| `cfg_strength` | 2.5 | **3.0** | 提高引导强度，更忠实于参考音频 |

**原理：**
- `nfe_step` (采样步数): 控制扩散模型的采样精度，步数越多，生成质量越高，但推理时间越长
- `cfg_strength` (引导强度): 控制模型对参考音频的忠实度，强度越高，音色克隆越准确

**预期提升：**
- PESQ: +0.1 ~ +0.3
- STOI: +0.02 ~ +0.05
- CSIG/CBAK/COVL: +0.1 ~ +0.2
- DNSMOS: +0.1 ~ +0.2

**代码位置：** `tts_batch_inference.py` 第 40-41 行

### 2. 评估脚本优化 ⭐⭐⭐⭐

**优化内容：**

1. **采样率处理**
   - 添加多采样率尝试机制（24000, 16000）
   - F5-TTS 默认采样率为 24000，确保评估使用正确采样率
   - 避免因采样率不匹配导致的评估错误

2. **DNSMOS 分数提取**
   - 改进字典值提取逻辑
   - 优先使用 OVRL（整体质量）作为主要分数
   - 添加 P808_MOS 作为备选分数
   - 处理各种返回值格式

3. **错误处理增强**
   - 完善的异常处理机制
   - 支持不同格式的返回值（字典、数值、列表等）
   - 更好的错误提示和日志

**代码位置：** `tts_evaluation.py`

### 3. 依赖环境优化 ⭐⭐⭐

- 确保所有评估依赖正确安装
- 验证 pesq, pystoi 等关键库可用性
- 修复 Windows 环境下的编码问题

## 🔍 发现的问题和解决方案

### 问题 1: 推理参数未优化
**问题：** 原始参数（nfe_step=100, cfg_strength=2.5）未充分利用模型能力
**解决：** 提升到 nfe_step=150, cfg_strength=3.0
**状态：** ✅ 已解决

### 问题 2: 评估脚本采样率处理不当
**问题：** 评估时可能使用错误的采样率，导致分数不准确
**解决：** 添加多采样率尝试机制，优先使用 24000
**状态：** ✅ 已解决

### 问题 3: DNSMOS 分数提取不完整
**问题：** DNSMOS 返回字典格式，原始代码可能无法正确提取
**解决：** 优化提取逻辑，优先使用 OVRL 分数
**状态：** ✅ 已解决

### 问题 4: 批量推理耗时较长
**问题：** 60+ 个文件，每个需要几分钟推理时间
**解决：** 
- 创建测试版本脚本（只处理前几个文件）
- 可以分批运行
- 建议使用多GPU并行处理（如果可用）
**状态：** ⚠️ 部分解决（需要硬件支持）

## 📈 进一步提高分数的方法

### 方法 1: 进一步增加采样步数
```python
NFE_STEP = 200  # 从 150 提升到 200
```
**优点：** 更高的生成质量
**缺点：** 推理时间显著增加（约 2-3 倍）
**建议：** 如果时间允许，可以尝试 200 甚至更高

### 方法 2: 调整引导强度
```python
CFG_STRENGTH = 3.5  # 从 3.0 提升到 3.5
```
**优点：** 更忠实于参考音频
**缺点：** 过高可能导致过度拟合，生成音频过于相似
**建议：** 在 2.5-3.5 之间测试，找到最佳平衡点

### 方法 3: 选择更好的参考音频
- 选择清晰、无噪声的参考音频
- 参考音频时长适中（3-6秒）
- 参考音频应该包含丰富的音色特征

### 方法 4: 优化微调训练参数
如果微调还未完成，可以考虑：
- 增加训练轮数（epochs）
- 调整学习率
- 使用更好的数据增强策略
- 增加正则化（weight_decay）

### 方法 5: 后处理优化
- 音频降噪
- 音量归一化
- 去除静音段

## ⚠️ 注意事项

1. **推理时间 vs 质量权衡**
   - 更高的 nfe_step 会显著增加推理时间
   - 建议在质量和速度之间找到平衡

2. **引导强度上限**
   - 过高的 cfg_strength 可能导致过度拟合
   - 建议不超过 3.5

3. **评估指标理解**
   - 不同指标关注不同方面（质量、可懂度、失真等）
   - 综合多个指标评估，不要只看单一指标

4. **硬件限制**
   - 批量推理需要足够的 GPU 内存
   - 如果内存不足，可以减少 batch_size 或分批处理
